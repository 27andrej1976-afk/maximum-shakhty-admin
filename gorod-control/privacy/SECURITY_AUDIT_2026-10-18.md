# Промежуточный аудит конфиденциальности — 18.10.2026

## Область проверки
Статическое чтение исходников ветки `privacy-hardening-2026-10-18`: Classic/Compact HTML, `city-map.js`, `MainActivity.java`, `WaterMonitorJobService.java`, `AndroidManifest.xml`. Проверки CI выполняют только статические регрессионные проверки. Они **не эквивалентны** проверке собранного APK или реального трафика телефона.

## Подтверждено исходниками
1. WebView локально сохраняет выбранный адрес и координаты в `localStorage`. Android сохраняет улицу и номер дома в `SharedPreferences`, чтобы фоновая проверка находила адресные совпадения.
2. В тестовой ветке добавлено удаление `localStorage` и синхронный сигнал на Android для очистки улицы/дома; при отсутствии локальной записи Java дополнительно удаляет устаревшую копию.
3. GPS и поиск адреса в Nominatim выполняются по отдельным действиям пользователя; тестовая ветка дополнительно спрашивает подтверждение **перед** запросом с точным адресом или координатами.
4. Есть выбор точки в центре карты с ручным вводом адреса без обращения **к Nominatim**. Эта функция не проверяет точность выбранной точки. Сама загрузка онлайн-карты может сообщать поставщику видимую область и IP.
5. Рендер карты загружает ресурсы `tiles.openfreemap.org` или `tile.openstreetmap.org`, а страница и сводки — с GitHub Pages. Полная нулевая передача сетевых метаданных не достигнута.
6. Android-фоновый монитор запрашивает публичный JSON городской сводки с GitHub Pages и сравнивает адреса **локально**. В запросе исходного кода фонового мониторинга нет домашнего адреса/номера дома как параметров.
7. Android Manifest содержит Интернет, геолокацию, уведомления, сеть, загрузку после перезагрузки и `allowBackup=false`. Контакты/микрофон/камера в просмотренном Manifest не запрашиваются. Итоговый merged manifest APK необходимо проверять отдельно.
8. Форма обращений по проверенному коду показывает выбранное фото локально и формирует черновик; окончательная подача происходит через Госуслуги пользователем. Не заявлять о серверной регистрации обращения.
9. Убрана зависимость от Google Fonts в обеих исходных HTML-страницах тестовой ветки.

## Выявленные ограничения
- **Не выполнен сетевой аудит самих v1.3 APK** (TLS/HTTPS запросы, WebView, фоновые операции при GPS и выборе точки, внешние ссылки и загрузка фото).
- **Не выполнена проверка новых privacy-изменений в Android WebView на реальном устройстве**. Текущие пользовательские APK v1.3 не включают изменения из этой ветки.
- Подтверждение согласия через системное `window.confirm` требует реального Android-тестирования: не считать UX проверенным, пока диалог не показан и не сработал в WebView.
- **Сохранение вручную выбранного центра карты** проверено только статически. В случае несовпадения фактического адреса и метки радиусные уведомления окажутся ошибочными.
- Карта и хостинг получают IP и запросы, а сторонний Nominatim получает полный адрес либо GPS-координаты **при явно подтверждённом запросе**.
- Не определён окончательный разработчик/оператор персональных данных и контакт для запросов.
- Не выпущена публичная окончательная политика; `PRIVACY_POLICY_DRAFT.md` — непубликуемый черновик.
- Сборка для RuStore должна иметь постоянную релизную подпись; нужны финальные Android тесты и проверка актуальных правил магазина.

## Релизный запрет до проверок
Нельзя характеризовать приложение как «не передающее никаких данных третьим лицам» и нельзя считать готовым к RuStore. Не переносить тестовую ветку в `main`, не публиковать новые APK, не изменять «Алису 2.0» без дополнительного согласования.

## Следующий обязательный практический тест
Создать изолированные тестовые Classic/Compact APK из ветки с privacy-поправками и пройти на Android: отказ от GPS; отмена передачи в Nominatim; ручной выбор карты; подтверждённый поиск адреса; сохранение/удаление и отсутствие фоновых совпадений по удалённому дому; запуск без интернета; отсутствие скрытой отправки текста/фото; протокол исходящих HTTPS доменов. Затем актуализировать политику по доказанному трафику.
