# Изолированный запуск на имеющемся FirstVDS

Подготовка для сервера №18772218. Существующая VNC-консоль ещё не открыта: автоматическая проверка отклонила наблюдение без явного согласия владельца на эту конкретную консоль. Не пробовать другой маршрут доступа в обход отказа.

Пакет формируется `prepare_deploy.py --output <каталог>`. Это не установка. В пакете нет сессии MAX, аккаунтов, подписного ключа или чужих проектов. Данные и код размещаются отдельно: `/opt/don-control`, `/etc/don-control`, `/var/lib/don-control`.

После разрешённого входа сначала подтвердить идентичность сервера, ОС, свободную память/диск, существующий HTTPS-vhost и занятые порты. Проверить резервное копирование конфигурации; не создавать платные ресурсы и не менять корневые маршруты Спортоскопа/ЛекалоAI.

Рабочая схема: отдельный пользователь `don-control` для MAX/SQLite, отдельный `don-web` для выдачи только публичной ленты, частные каталог сессии и state с правами 0700. У веб-процесса нет прав на чтение MAX-сессии. Python/venv устанавливаются из существующей системы и закреплённого пакета PyPI. Публичный сервис слушает только `127.0.0.1:8791`, HTTPS обеспечивает проверенная конфигурация Nginx.

Сервисы: `don-collector.service` и `don-public.service`. Пример collector-конфигурации и отдельного location приложен. Перед reload требуется успешный `nginx -t`. Сессия переносится приватно, никогда через публичную папку/репозиторий. Частные файлы не включать в публичные резервные копии сайта.

Не запускать выпуск с тестовыми адресами. Черновой реестр и пустой каталог не включены автоматически: worker отказывается объявлять сбор подключённым. Перед живым запуском подтвердить профильные источники, территориальный каталог и обработку публикаций. HTTP `/healthz` подтверждает только работу веб-процесса; `incidentPipelineVerified:false` не превращается в успешный запуск аварийной карты.

После развёртывания проверить: HTTPS/изолированный путь; повторное чтение MAX; новый и сохранённый event/feed; отключение одного источника; перезапуск с сохранением SQLite; правило восстановления/36 часов; отсутствие сессии/SQLite в HTTP; получение ленты Android WebView. Существующие проекты проверить отдельно после Nginx reload.
