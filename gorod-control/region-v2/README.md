Будущие обновления сохраняют новый ID и подпись; обновление через RuStore зависит также от настроек/разрешений магазина на устройстве.

Предыдущая попытка git push была отклонена автоматической проверкой; обходить это ограничение нельзя.

## Что работает в локальном коде

### Сбор и хранение

`collector.py` использует pinned MAX SDK `maxapi-python==2.4.1`: только проверенные ID публичных каналов, без отправки сообщений, отметок о прочтении, новых подписок и интерактивного входа.

Страницы истории и позиция продолжения пишутся одной транзакцией SQLite. После перезапуска загрузка продолжается. Повторные ID не создают дублей, редакции сохраняются отдельно. Checkpoint и lastSuccess не становятся новыми после частичного чтения. Сбой одного канала не останавливает остальные.

На границах страниц есть перекрытие. Если временную границу нельзя пройти безопасно (100 сообщений с одной меткой времени), остаётся GAP. Короткая граничная страница трактуется как полная в пределах лимита API; этот контракт нужно подтвердить с реальным MAX. Первый импорт ограничен 16 днями и не заявляет полноту более старой истории. Последующие импорты доходят до прежнего checkpoint с перекрытием 24 часа даже после длительного простоя. Старые правки вне перекрытия, удалённые публикации и недоступная серверу история всё ещё могут быть пропущены — нужен отдельный механизм полной сверки.

Публикации без текста, пересылки и вложения не теряются молча: сохраняются текст, ID, даты и типы/количество вложений, а запись требует разбора. Медиафайлы и временные подписанные URL пока не сохраняются, распознавания вложений нет.

### Из публикаций в события

`events.py` — журнал событий с привязкой к существующей MAX-публикации и её точному хешу. Проверенный парсер или оператор передаёт структурированные records: источник, ID публикации, хеш, категория, территория, проверенные ID адресов и сроки. Это **не готовый автоматический разбор русскоязычных объявлений**. Пока нет такого records, публикация остаётся в очереди, а не превращается в придуманную метку.

Пакет records применяется атомарно. Несовпадение исходного хеша, территории, категории, времени или адресного справочника отклоняется. Одинаковое название улицы в разных городах не является совпадением. Повторный review не создаёт дубль. Изменённая публикация оставляет старое событие до истечения срока, с пометкой о необходимости проверки.

Подтверждение восстановления закрывает только явно перечисленные адреса конкретного события. Полное подтверждение снимает всё событие при обработке. Отказ источника не удаляет его. Для воды/света/газа без подтверждения действует модель 36 часов: от заявленного окончания, иначе начала, иначе публикации. Повторное чтение срок не продлевает. Это реализовано в Python и клиентской фильтрации, но ещё не проверено в Android.

Предупреждения МЧС имеют официальный срок и не получают лишние 36 часов. Региональное предупреждение не требует фиктивной точки и доступно во всех городах и режимах радиуса; для него источник должен иметь отдельно подтверждённый областной охват. Явная отмена закрывает такое предупреждение. Публикации без установленного срока остаются на проверке.

`export_feed.py` формирует ленту для интерфейса. `health.py` раздельно показывает lastAttempt, lastSuccess, GAP, неизвестный охват и непрочитанные каналы. Прочитанный источник не доказывает полноту публикаций или отсутствие аварий.

### Экран приложения

`web/` — работающий браузерный клиент, связанный с JSON-лентой:

- оригинальные логотип группы и герб области, областная подпись;
- карта Leaflet, категории «Все», вода, свет, газ, МЧС;
- «Рядом» / «Весь город» / «Вся область» в зависимости от выбранной территории;
- геолокация запрашивается только по нажатию, последняя точка хранится локально; фонового отслеживания пока нет;
- выбор радиуса 1/3/5 км, сохранение территории/фильтра/радиуса после перезапуска;
- карточки с датой, адресами, первоисточником, частичным восстановлением;
- только адреса с geometryVerified и допустимыми координатами получают метки;
- сохранённая сводка остаётся при недоступном сервере, но источник не становится зелёным;
- неверный формат новой ленты не заменяет сохранённую; истечение срока проверяется и клиентом;
- необработанные публикации доступны отдельно и не выдают себя за аварии;
- рекламный слот зарезервирован в структуре, по умолчанию скрыт, рекламного SDK/кампаний нет.

«Сообщить о проблеме» пока **не подключено** к проверенным муниципальным адресатам: кнопка явно пишет, что сообщение не отправлено. Геолокация на физическом устройстве и поведение Android WebView не проверены. Правомерность использования герба в коммерческом launcher-значке должна быть проверена до релиза; визуальный ресурс не является правовым разрешением.

`build_client.py` только копирует web-ресурсы в заданный каталог; не собирает APK, не подключает MAX и ничего не публикует. Без --feed создаёт пустую production-ленту с неизвестным охватом. QA-данные не подставляются автоматически.

Постоянный каталог состояния нельзя размещать только в одноразовом runner. Сессия и ключ APK не должны попадать в публичный каталог/репозиторий.

```sh
  --registry /private/verified-sources.json --state-dir /private/don-state \
  --session-dir /private/max-session --municipality verified-gar-id \
  --health-output /public/health.json --catalog /private/verified-catalog.json \
  --feed-output /public/feed.json

python gorod-control/region-v2/export_feed.py \
  --registry /private/verified-sources.json --state-dir /private/don-state \
  --catalog /private/verified-catalog.json --reviews /private/parser-records.json \
  --output /public/feed.json

```

## Подготовка повторного входа

`windows-renew/` — исходный запуск для Windows 10/11 с Python 3.10+. Создаёт отдельную новую папку сессии, не изменяет старую, показывает QR локально и проверяет только три прежних публичных канала. Свой буфер после подтверждения очищается только при совпадении с собственным значением, а не произвольно.
