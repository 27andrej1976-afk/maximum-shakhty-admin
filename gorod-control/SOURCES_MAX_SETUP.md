# Проверка источников и MAX — тестовая доработка от 20.10.2026

## Найденная причина «Проверено 3 из 11»

Счётчик `renderSources` считал только `status == ok`. Успешное чтение
RSS/канала без подходящих местных объявлений получало `partial`, как и
неподтверждённый охват. Поэтому счётчик не показывал число попыток проверки.
Список также повторяет RSS и канал администрации для разных категорий.
Одиннадцать строк не являются одиннадцатью независимыми ресурсами.

На момент ручной проверки обе резервные RSS отвечали HTTP 200. УРСВ
из среды разработки отвечал HTTP 403 (на скриншоте телефона — HTTP 404).
Это разные результаты из разных сетей. Исправление доступности УРСВ
не подтверждено. Страницы MAX содержали карточку канала без списка постов.

## Подготовлено

- Отдельное поле `readStatus`: успешное чтение не приравнивается к полному
  охвату отключений; отсутствие совпадений не является сетевой ошибкой.
- Счётчик прочитанных строк, ошибок и отсутствующих настроек; пояснение
  повторяющихся источников. Просроченные проверки не считаются свежими.
- Серверный GET-клиент официального MAX API с явными статусами ошибок,
  отсутствующего доступа, проверкой ID канала, времени и размера ответа.
  Токен передаётся только в заголовке Authorization.
- MAX добавлен в сборщик тестовой сводки и шаблон следующей APK.

## Что требуется для настоящего подключения

Официальная документация: https://dev.max.ru/docs-api/methods/GET/messages

`GET /messages?chat_id=...` доступен боту, который является администратором
соответствующего канала и имеет право чтения. Публичная ссылка и личная
подписка не заменяют эти права.

Каналы:

- https://max.ru/shakhtygorod — администрация города Шахты;
- https://max.ru/id6163089292_biz — АО «Донэнерго», аварийные отключения.

После предоставления доступа владельцами каналов настройте на сервере:

- secret `MAX_BOT_TOKEN`;
- variable `MAX_CITY_CHAT_ID`;
- variable `MAX_POWER_CHAT_ID`.

Не помещать токен в переписку, исходники, APK, публичный JSON или URL.
Достаточно прав чтения; приложение не отправляет публикации в каналы.

## Предел готовности

Доступ к реальному MAX API ещё не проверен: токена и назначений бота нет.
Проверены сценарии на локальных фикстурах. Клиент читает до 100 последних
публикаций, полнота истории не гарантируется. События MAX помечены
`requiresReview=true`: автоматические тревоги остаются выключены до проверки
на реальных сообщениях, включая восстановления и повторные объявления.
Потребуется проверка Classic/Compact при следующей согласованной сборке.
Рабочая ветка main и ранее установленные APK этой доработкой не заменяются.
