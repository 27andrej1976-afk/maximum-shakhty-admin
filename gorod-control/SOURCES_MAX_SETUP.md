# Проверка источников и MAX — тестовая доработка от 20.10.2026

## Найденная причина «Проверено 3 из 11»

Счётчик `renderSources` считал только `status == ok`. Успешное чтение
RSS/канала без подходящих местных объявлений получало `partial`, как и
неподтверждённый охват. Поэтому счётчик не показывал число попыток проверки.
Список также повторяет RSS и канал администрации для разных категорий.
Одиннадцать строк не являются одиннадцатью независимыми ресурсами.

На момент ручной проверки обе резервные RSS отвечали HTTP 200. УРСВ
из среды разработки отвечал HTTP 403 (на скриншоте телефона — HTTP 404).
Это разные результаты из разных сетей. Исправление доступности УРСВ
не подтверждено. Страницы MAX содержали карточку канала без списка постов.

## Подготовлено

- Отдельное поле `readStatus`: успешное чтение не приравнивается к полному
  охвату отключений; отсутствие совпадений не является сетевой ошибкой.
- Счётчик прочитанных строк, ошибок и отсутствующих настроек; пояснение
  повторяющихся источников. Просроченные проверки не считаются свежими.
- Серверный GET-клиент официального MAX API с явными статусами ошибок,
  отсутствующего доступа, проверкой ID канала, времени и размера ответа.
  Токен передаётся только в заголовке Authorization.
- MAX добавлен в сборщик тестовой сводки и шаблон следующей APK.

## Что требуется для настоящего подключения

Официальная документация: https://dev.max.ru/docs-api/methods/GET/messages

`GET /messages?chat_id=...` доступен боту, который является администратором
соответствующего канала и имеет право чтения. Публичная ссылка и личная
подписка не заменяют эти права.

Каналы:

- https://max.ru/shakhtygorod — администрация города Шахты;
- https://max.ru/id6163089292_biz — АО «Донэнерго», аварийные отключения.

После предоставления доступа владельцами каналов настройте на сервере:

- secret `MAX_BOT_TOKEN`;
- variable `MAX_CITY_CHAT_ID`;
- variable `MAX_POWER_CHAT_ID`.

Не помещать токен в переписку, исходники, APK, публичный JSON или URL.
Достаточно прав чтения; приложение не отправляет публикации в каналы.

## Предел готовности

Доступ к реальному MAX API ещё не проверен: токена и назначений бота нет.
Проверены сценарии на локальных фикстурах. Клиент читает до 100 последних
публикаций, полнота истории не гарантируется. События MAX помечены
`requiresReview=true`: автоматические тревоги остаются выключены до проверки
на реальных сообщениях, включая восстановления и повторные объявления.
Поддерживается только Compact в water-v16; обычные APK сняты с публикации.
MAX не считается подключённым до проверки реальных прав и чтения канала.


## Резервный мониторинг воды

- `secondary_water.py`: https://kvu.su/utilities/rss.xml — отдельные сообщения СМИ;
  принимаются адресные объявления о ремонте с указанным сроком, не общие статьи.
- `rss_water.py`: перепечатки с документом УРСВ или точным авторством
  «Администрация города Шахты». Последние имеют origin `municipal_repost`,
  не выдаются за прямое чтение MAX.
- Один материал с несколькими ремонтами разбивается на отдельные события.
  Объединение публикаций — только при точном совпадении места ремонта, времени
  и разобранного адресного охвата. Все ссылки сохраняются в `evidence`.
- Неуказанный тип улицы не угадывается. Такие события требуют уточнения.
  Ожидаемый срок окончания не считается подтверждением восстановления.
- Новые источники отображаются в веб-версии и компактных APK. Старые APK содержат
  собственный интерфейс и не поддерживают новые origin без переустановки.
- Фоновые уведомления Android от вторичных источников пока не включены;
  сведения доступны при открытии и обновлении приложения. Прежние уведомления
  из поддерживаемых официальных источников сохраняются.

## Пользовательская сессия MAX — подготовлено 21.10.2026

Официальный Bot API не единственный технический путь: добавлен необязательный `max_user_reader.py` на PyMax 2.4.1. Читает только два заранее заданных публичных канала, проверяет ID/тип/публичность/название, не запрашивает историю личных чатов и не отправляет сообщений. QR-авторизация выполняется локальным Windows-коннектором, облачные задания не могут запускать новый вход.

Для подключения используется GitHub Actions Secret `MAX_USER_SESSION_B64`. Значение содержит сессию всего MAX-аккаунта (не ограниченный двумя каналами токен), поэтому предпочтителен отдельный аккаунт. Код фильтрует чтение; технические права самой сессии шире. Сессия не должна попадать в репозиторий, артефакты сборки или чат. История и источники считаются прочитанными только после реального успешного ответа. При отсутствии секрета прежний Bot API и текущие источники работают как раньше.

Реальное получение QR проверено без авторизации аккаунта. Чтение пользовательских каналов требует подтверждения входа владельцем. До сверки реальных публикаций MAX-события остаются `requiresReview=true` и не создают автоматические уведомления.

Пошаговый запуск: `max-reader/README.md`. Сборка Windows-коннектора не пересобирает Android-приложение.
